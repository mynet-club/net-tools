| 区 | 内容 | 为什么这么摆 |
|---|---|---|
| 顶部横幅 | 非 enforce 时的「窗口不会采集任何记录」 | 「开关是开的、窗口是空的」是这一屏最容易误读的状态，必须比统计更显眼 |

1. **导出走原始字节**：`res.text()` 之后直接喂 Blob，不做「解析再拼回去」。字段顺序与数字

   同一个窗口，浏览器下载的那份与 `llmproxy replay collect -out` 的那份 **sha256 相同**，

2. **模式联动**：策略屏每次刷新（含改 mode）都带着回放屏重读一次。窗口收不收得到记录完全
   由 `policy.mode` 决定，两屏各自独立就会各说各话。
3. **被拒的提交要把服务端口径盖回输入框**：400 意味着窗口一个字都没动，留着那串确定无效

**这一包顺手修掉一处演练脚本自身口径**（第三类失败，不是代码缺陷）：
`drill-release-artifact.sh` 判「优雅退出」用的是 `pgrep -f "$BIN"`，按**命令行字符串**匹配，
于是任何把那条二进制路径写进自己参数的进程（这次是同一条 ssh 命令里紧跟着跑的那个
`LLMPROXY_BIN=… bash scripts/e2e-multiuser.sh` 外层 shell）都会被报成
`DRILL_FAIL(代码): stop 之后进程还在`，而同一份日志里服务端的 `已退出` 与
「stop 之后仍在应答」那一格都说明进程已经退了。害处是**归因**：脚本口径被标成代码失败，
下一个人去查网关的退出路径。改成启动时读 `$LLMPROXY_HOME/llmproxy.pid` 拿到服务端 pid，
stop 后用 `kill -0` 判那一个进程，并断言 pid 文件已清掉。逐条对账在
`docs/3.0-verification.md` §23.9。

**还有一处第三类失败，出在这套文档自己身上**：§23.10 原文写「远端 `release-check.sh --3p0`
会自己重跑四平台构建，重跑之后 sha256 仍是同一个值」—— 而 `release-check.sh:187` 的注释就写着
`--pkg / --3p0 都只做定向检查，不动构建产物`。那次「两端同值」核对的是被 rsync 带过去的同一个文件，
它证明传输没坏字节，**不证明重建可复现**。脚本那处至少报过红，文档这处一直绿着 —— 归因更难查。
按真做法重跑之后能立的口径是：**同一台机器、同一份源码，两次 `build.sh` 的可执行文件逐字节相同
（linux-amd64 `2065ddad…`、darwin-arm64 `f30c16e4…`）；`.tar.gz` 本身不承诺（`build.sh:80` 用裸
`tar -czf`，没做 mtime/uid 归一，两次构建包 sha 就不同）；跨机不承诺（本机 Go 1.26.0、
远端 Go 1.27.1，远端自建 linux-amd64 二进制 = `e85f1d3c…`）**。要不要把包级复现也钉住
（`--mtime --sort=name --owner=0 --group=0` + gzip `-n`）属于构建脚本变更，交主线。
**2026-10-05 §0.1 第 21′ 行已裁决：不改 `build.sh`** —— 能立的就是上面那句，
**校验和不当作可复现凭证**，README 与交付说明的文案随 P9 按这句改。
逐条读数在 `docs/3.0-verification.md` §23.12。

来自服务端字段（界面没自己拼那句话）；导出文件 `schema_version=2` 且选路记录带
`replay_snapshot`，交给 `replay run` 得到 `routing/… passed [首选逐位]`、
`首选逐位复现 1`。三条拒绝路径（`2000` / `not-a-scope` / `abc`）各自红在该红的地方，
且 400 之后输入框回显的是服务端的真实值 —— 指针语义的界面不许留下「说改了其实没改」。
细节记在 `docs/3.0-verification.md` §20.7。

§3.2 那一包的演练口径是「先出产物，再让产物自己跑」：

```bash
./scripts/release-check.sh                                    # 出 dist/ 四个 tar.gz + SHA256SUMS
./scripts/drill-release-artifact.sh                           # ✓ 五项留痕：sha256/版本/启动/优雅退出/重开
tar -xzf dist/llmproxy-v2.5.0-dirty-darwin-arm64.tar.gz -C /tmp/drill
export ART=/tmp/drill/llmproxy-v2.5.0-dirty-darwin-arm64/llmproxy
LLMPROXY_BIN=$ART bash scripts/e2e-multiuser.sh                # ✓ 同一套 189 项，跑在发行件上（amd64 那个架构同样 0 失败）
LLMPROXY_BIN=$ART KEEP=1 bash scripts/e2e-multiuser.sh          # 留住运行时目录，拿 records.json
# 同一份记录，每次只变一样：二进制、policy.mode、时钟、目录
LLMPROXY_HOME=<留住的目录> $ART replay run -records <目录>/records.json -now "$(date -u -v+2d +%FT%TZ)"
```

实测四段都是「记录 3 条：通过 3，差异 0，拒绝回放 0」，并且报告照实附一行「只做解释性回放，
不比对首选顺序」；两条失败对照（配置缺 providers、策略包内容文件被挪走）都是点名拒因，
不是「0 条差异」。

## 6. 交接规则（本仓库当前生效）

- 每个工作包**只在本地提交**，不推送；推送由用户决定。
- `git add` 必须按文件名点名：仓库里同时存在与 3.0 无关的改动
  （`subserver/`、`mihomo/`、`smartxray/`、`litellm-proxy/`、`smartxray-go/`、`.DS_Store`、
  `docs/optimization-plan.md` 等），禁止 `git add -A`。
- 只用 Go 标准库，不新增依赖、不动 `go.mod`；注释与对外文案一律中文。
- 审计、detail、日志里不得出现密钥明文或未脱敏正文；界面不重算权限与费用。
