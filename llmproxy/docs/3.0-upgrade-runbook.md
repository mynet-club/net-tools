## 1. 定位目标

确认主机、服务管理方式、可执行文件路径、运行时目录、数据库驱动、当前版本与监听地址。只回显非敏感信息，禁止输出 API key、DSN 密码或 `master.key` 内容。

## 2. 冻结候选产物

完成全量测试与静态检查；使用现有构建流程生成产物，记录源码提交、实际版本串、包与二进制 SHA-256。版本若带 dirty 必须如实记录。使用该产物在隔离目录完成发行件生命周期演练与 e2e。

## 3. 备份与迁移预演

优雅停止目标后获取一致性备份：旧二进制、配置、策略包、处理器参数、数据库及主密钥。密钥备份收紧权限并与对外验收报告分离。

SQLite 备份应包含一致性检查，不能只复制正在写入的主文件而忽略 WAL。MySQL/PostgreSQL 必须先完成库外备份和恢复验证，才可确认迁移备份门；不能为绕过启动拒绝提前设置确认变量。

在隔离副本上运行新版本迁移，核对 schema 版本、行数、scope 映射、价格与冻结金额、用户和审计记录。验证新进程重开库，并验证旧二进制配合旧库备份可恢复。迁移后不能只换旧二进制而继续使用新 schema。

## 4. 切换与验收

替换候选二进制，先保持现有策略模式，验证健康、鉴权、模型目录、非流式、SSE、记账和管理台。模型请求使用用户授权的测试范围。

再分范围启用 shadow/enforce，核对拒绝零出网、隐私约束、组织权限、回放和审计。知识正文注入开关保持显式授权，不因升级自动开启。

## 5. 回滚与结案

启动失败、迁移校验不一致、鉴权异常或费用归属错误时停止继续切换。恢复成套旧二进制、配置、数据库与匹配主密钥；若升级后已有新请求，先保全新增数据再恢复，说明回滚窗口内的数据处理方式。

验收记录包含目标、版本、产物摘要、备份位置（不带密钥）、迁移结果、烟测结果和剩余限制。仅在实测后标记“3.0 自用部署已验收”。
