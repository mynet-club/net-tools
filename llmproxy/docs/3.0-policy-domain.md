# llmproxy 3.0 领域模型与策略内核（工作包 A）

本文是 `internal/policy/` 的接口契约。主线以本文为准冻结领域对象：B（身份）、C（知识）、D（路由）、E（处理器）、F（执行器）只引用本包类型，**不得复制结构体或自带一套判定次序**（AGENTS/手册 §5）。

## 1. 包边界

`internal/policy` 只有领域对象与纯函数：不 import `net/http`、不 import 数据库、不读配置文件、不依赖 `internal/config`。运行期结构（供应商配置、用户行、HTTP 请求）由各适配层转换成本包对象后再进来。

求值不吃外部可变状态：`now` 一律显式传参。这是「同一输入同一输出」的前提。

## 2. 对象清单

| 类型 | 位置 | 职责 | 关键约束 |
|---|---|---|---|
| `ScopeRef` | scope.go | 结构化范围引用 | `Kind ∈ {user, organization, project, system}`；ID 禁冒号/空白/控制字符，≤256 字节；`Display()` 只进日志，禁止当存储键 |
| `ScopeSelector` / `ScopeChain` | scope.go | 规则里的范围选择器 / 一次判定覆盖的范围集合 | 选择器只有 `*`、`kind:*`、`kind:id` 三种形式，裸用户名直接报错 |
| `Identity` | identity.go | 已认证主体快照 | subject 必须稳定 ID：拒邮箱形态、拒等于显示名、拒含空白；带 roles/groups/projects 就必须带 `ExpiresAt` |
| `DataLevel` | datalevel.go | 四级数据分级 | 零值是 `LevelUnknown` 而非 public；比较只走 `AtLeast/Exceeds`，禁止字符串序 |
| `BodyAccess` | bodyaccess.go | 正文访问三档 | 空串解析为 `metadata-only`；档位集合封闭 |
| `Entitlement` | entitlement.go | 一条授权规则 | `Effect ∈ {allow, deny}`；通配只许尾部（`model:*`）；conditions 语义见 §4 |
| `PolicyContext` | context.go | 一次判定的上下文 | `Purpose` 必填；`DataLevel` 必须已判定；给了 `Project` 就必须给 `Organization` |
| `PolicyBundle` / `BundleSet` | bundle.go | 带版本的策略包 / 实际加载的包集合 | `Version ≥ 1`；同 ID 不许出现两个版本；空集合不出版本串 |
| `Resolver` | resolver.go | 判定内核 | 构造后不可变，可并发复用；`version` 必须来自 `BundleSet.PolicyVersion()` |
| `Decision` / `MatchedRule` | decision.go | 判定结果与命中链 | `Matched[0]` 是决定性规则；`Explain()` 不得含 conditions 取值 |
| `Reason` | decision.go | 稳定原因码枚举 | 未注册的原因码在计划校验时直接失败 |
| `RouteCandidate` / `Rejection` / `RoutingPlan` | plan.go | 路由计划 | 必须带 `PolicyVersion` 与 `ExpiresAt`；候选不得含 base_url/密钥 |

资源与动作词表（同文件）：命名空间 `model / capability / knowledge / processor / budget / body`，动作 `use / read / invoke / spend`。`ResourceBodyRaw = "body.raw"` 是原文出网授权的资源名。

## 3. 判定顺序（唯一的业务规则源）

`Resolver.Evaluate(ctx, chain, resource, action, now)`：

1. `ctx.Validate()` 失败 → 拒绝，`context_invalid` / `identity_missing`；
2. `Identity.ValidAt(now)` 失败 → 拒绝，`identity_expired` / `identity_not_yet`；
3. 版本串为空 → 拒绝，`policy_version_missing`；
4. `chain` 为空 → 拒绝，`scope_mismatch`（漏传范围不能被解释成「不限范围」）；
5. 逐条规则过滤：资源通配匹配 → 动作匹配 → **范围命中 chain 任一项** → 主体选择器命中（给出档位）→ 未过期 → conditions 成立；
6. 命中集合按 `deny > explicit_allow > group_allow > default` 排序，同档再按 `Entitlement.SortKey()`；
7. 无命中 → 拒绝，原因优先级为 `entitlement_expired` > `data_level_denied` > `model_not_allowed`（模型资源）> `no_matching_rule`。

**缺席即否**：没有任何规则命中时结果是拒绝，不是放行。

主体选择器：`*`（兜底档）、裸 subject（explicit 档）、`role:` / `group:` / `project:` / `organization:`（group 档）。前缀集合封闭，含未知前缀的 subject 在选择器解析期报错。

## 4. Conditions 是规则的前置条件

所有 conditions 键对 allow 与 deny 语义完全一致：**成立则规则生效，不成立则规则不参与**。分级用两个显式方向键，避免出现「给 deny 写上界反而把禁令跳过」：

- `max-data-level: confidential` → ctx 分级高于 confidential 时不成立；
- `min-data-level: confidential` → ctx 分级低于 confidential 时不成立；
- `role` / `group` / `auth-method` → 成员关系（大小写敏感）；
- `purpose` / `organization` / `project` / `source` / `data-level` → 字符串精确相等；
- 未知键 → 一律不成立（fail-closed）。新增事实必须在本包扩保留键并升级策略版本。

多条键同时不成立时，返回哪个原因码与 map 遍历顺序无关（按键排序遍历）。

## 5. 范围集合（本次修正的根因）

手册 §2.7 要求结构化 scope，但一个请求**同时**属于 `user:alice`、`organization:university`、`project:proj-lab-7`。若判定只接一个 `ScopeRef`，组织级与项目级策略对个体请求永不生效。

因此判定、规则并集、策略包过滤一律接 `ScopeChain`：规则命中集合中任一范围即参与判定，优先级仍由 `Resolver` 唯一决定。范围之间的父子归属由各适配器（B/G）展开成完整 chain 传进来，本包不猜层级。

`PolicyBundle.Covers` 的定义：`system` 类型包对任意 chain 生效；其余包必须精确命中 chain 里的某个范围。

## 6. 版本与回放

- `BundleSet.PolicyVersion()` = 按（范围、ID）稳定排序后的 `id@version` 用 `|` 连接。构造顺序不影响结果（有测试固定这一点）。
- `BundleSet.Filter(chain)` 给出实际作用于该 chain 的子集；**`RoutingPlan.PolicyVersion` 与审计版本必须取子集版本**，不是全集版本。
- `DeriveRoutingSeed(requestID, policyVersion, routingEpoch)` 实现 §2.8 的 seed 派生，输入带长度前缀，避免拼接歧义。本包只派生 seed，**抽样算法在 D**。
- `RoutingPlan.Digest()` / `CandidatesDigest()` 在摘要前做稳定排序，用于「同输入同计划」的回归断言。
- `Decision.ExpiresAt` 取「命中规则与身份的较早到期点」，是下游缓存判定的 TTL 上限。

## 7. 与手册的两处增量（需主线确认）

1. `RoutingPlan` 除手册的九个字段外，带 `RoutingSeed` 与 `Rejections`。前者是 §2.8 要求在线记录的字段，后者是 §6 要求可验证的候选排除原因。纯增量，序列化后直接进审计。
2. 判定入口收 `ScopeChain` 而非单个 `ScopeRef`（理由见 §5）。

`Rejections`/`RouteCandidate` 都不含 `base_url`、密钥或正文；`leak_test.go` 用反射把「领域对象不得携带 body/凭证类字段」变成会失败的断言。

## 8. 各包接什么

- **B**：把 OIDC claims 映射成 `Identity`（roles/groups/projects 必须带 TTL）+ `ScopeChain`（展开组织与项目归属）。不参与判定。
- **C**：`knowledge:<id>` 资源 + `ActionRead`；知识库等级作为 `EffectiveLevel` 的 `knowledge_level` 入参。
- **D**：消费 `PolicyContext.AllowedRegions` 与 `RouteCandidate.MaxDataLevel`；输出 `RoutingPlan`，`PolicyVersion` 取自 `Filter(chain)`。排除候选时填 `Rejections` 的注册原因码。
- **E**：`ProcessorSpec.BodyAccess` 用本包 `BodyAccess`；原文出网走 `Resolver.AllowsRawBody`（要求授权自身带期限，通配放行不算授权）。
- **F**：只读 `RoutingPlan`，不写费用与审计结论。

```bash
cd llmproxy && go test -race -count=1 ./internal/policy/
```

覆盖：正常/拒绝路径、规则与身份过期、版本变更与顺序无关性、条件语义、跨组织隔离、原文授权两道门槛、判定并发（`-race`）、输出不泄露 conditions 取值与正文/凭证字段、seed 派生确定性与拼接歧义。

## 10. 已知限制

- 预算（`budget:` 资源）只有命名空间词表，没有额度求值——配额语义仍在 `internal/server/limits.go` 与 `internal/store`，接线时由主线决定迁移边界（手册禁止执行器直接写费用表）。
- 策略包加载（YAML → `PolicyBundle`）不在本包：A 禁止读配置文件，加载器归 H/接线包。
- `ReasonRegionDenied` 已注册但本包不产生它——区域约束的实际排除发生在 D 的候选过滤里。
- 没有实现 SAML/LDAP/OIDC 的任何解析（归 B）。
