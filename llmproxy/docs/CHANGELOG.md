# 变更记录

版本号由 git tag（`llmproxy-v*`）在构建时注入；发行版号只有一个来源，见 README「版本号由构建注入」。

## v2.0.0 — 2026-09-26

从 1.9.x 开发线（`v1.9.20-dev` 及之后的本地构建）收束成的第一个正式大版本。
**数据库 schema 无变更**，从 1.9.x 直接换二进制即可；回滚见文末。

### 路由语义（破坏性，有意为之）

- **点名映射独占**：只要有人点名声明了某个下游模型名，`models: ["*"]` / catch-all
  的万能匹配上游**整档出局**。以前是「点名优先、通配垫底」，结果 mimo 这类名字
  会被串到根本不认它的直通上游上吃 400。
- 点名那家被重试排除时，**不**落到万能匹配（映射还在，只是这轮跳过）；多家点名则走另一家。
- 用户台映射表单改为四选一：**不映射 / 直通 / 列表 / 自定义**，不再用「留空」一词两义。
  给万能匹配的家加点名映射时**保留**它的 `catch_all`（其它模型仍可兜底）。

### 安全

- **拨号层最终 IP 校验**：配置层的 `CheckUpstreamEgress` 只看得到校验那一刻的 DNS，
  域名在校验后改指到 `169.254.169.254` 能绕过去（rebinding）。现在：
  - 直连在 `net.Dialer.Control` 里对**最终解析 IP** 再判一次；
  - 代理路径在建隧道前判目标主机；
  - 只对**用户可控上游**生效，系统池仍归运营者；
  - 两档界线不变：link-local（含云元数据）一律拒；回环/私网跟 `server.block_local_upstream`。
- `/discover` 增加频率与并发闸门：全局并发 4、单用户每分钟 10 次（不限就是免费内网扫描器）。
- 用户自有上游数量上限 32。
- Transport 缓存 LRU 上限 64（以前无界，用户可控代理 URL 可以吃内存）。
- 删除 `forwarder` 里的 TEMP 调试日志。
- `serviceResponding(nil)` 不再猜默认端口：配置读不出来时探 `127.0.0.1:8787`，
  会把任何回 200 的服务当成 llmproxy，进而给无关 pid 发终止信号。

### 账本一致性

- **金额算法统一下沉 `store.RowCharge`**：CLI、API、服务端共用一份。
  以前 `cmd/llmproxy` 里有一份简化副本（`rowChargeOf`），两边一旦漂移就
  「CLI 报一个数、API 报另一个数」。
- 改价**不**重算历史：已冻结的请求永远按它当时冻结的金额计（有回归测试钉住）。
- 删用户后重建同名用户不继承前任的模型授权与熔断状态；用量账单保留。

### 性能与并发

- 限流/配额热路径改为 **map 读写锁 + 每用户一把锁**：装载当月基数只挡该用户，
  别人的判断照常走。以前整张表一把互斥锁，多用户高并发时 Acquire/CheckQuota/Add 全串行。
- 用量报表加 **5 秒 TTL 缓存**：界面轮询是热点，每次都现算会占满 store 那条唯一
  SQLite 连接。配额判断不走这份缓存。改价、删用户、SIGHUP 会主动失效。

### 测试

- 拨号拦截、DNS rebinding 替身、discover 闸门不漏槽、provider 超限、Transport 缓存边界
- 重启恢复（用户/价目/冻结金额/熔断状态）、改价不重算历史
- 金额算法（冻结优先、失败不进分母）下沉到 `store` 后跟过去

## 1.9.x 开发线（未打 tag，摘要）

本地构建号为 `v1.9.x-dev`，主要能力：

- 消费模式：多用户、BYO 上游、系统池、混合模式（自有优先、全挂回落系统池）
- 两层价目（上游成本 / 分发价）、按请求开始时刻**冻结**、峰谷时段系数、规则 B 择廉
- 会话粘性 `(用户, 会话, 模型)`、粘性失败漂移、熔断按用户隔离
- 流式空闲看门狗（不再按总时长掐）、客户端断开不赖供应商
- 上游密钥 AES-256-GCM 落库、`block_local_upstream` 出网校验、CORS
- 网页控制台（管理台 + 用户台）、CLI（`admin`/`config`/`price`/`status`）
- 交叉编译发布：macOS/Linux × amd64/arm64 + SHA256

## 回滚说明

### 二进制

```bash
# 保留旧二进制
cp -p /opt/llmproxy/llmproxy /opt/llmproxy/llmproxy.v2.0.0.bak

# 换回 1.9.x 构建（dist/ 里有 llmproxy-v1.9.20-dev-*）
# 解压后覆盖 llmproxy，再
llmproxy restart
```

### 数据库

**v2.0.0 没有 schema 变更**，直接换回旧二进制即可，数据原样可用。

若将来出现 schema 变更，必须遵守：

1. 迁移脚本只做**加列/加表**，不删不改语义；
2. 回滚前先 `sqlite3 <db> .dump` 留一份；
3. 旧版本遇到新列应当忽略（SQLite 默认行为），但**新列若参与计费**则禁止回滚
   到不认识它的版本 —— 那会让冻结金额被当成 0。

### 配置

v2.0.0 未删任何配置项。`server.block_local_upstream` 语义不变（默认仍允许本机
ollama / 回环假上游）。新上限（discover 频率、用户上游数、Transport 缓存）是
硬编码常量，不是配置项，回滚时也无残留。

### 不兼容点（回滚到更早版本时注意）

- **点名映射独占**是行为变更：回滚到旧版后，「点名 + 万能并存」会重新变成
  「万能垫底」，可能再次把特定模型名串到直通上游。
- 用户台映射表单的四选一在旧版服务端上仍是合法的 `map[down]=up` 写法，
  但「直通」会写成同名点名映射 —— 旧版把它当普通映射，行为一致。
